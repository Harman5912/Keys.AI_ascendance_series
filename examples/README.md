## Provenance, stated plainly

**Planned by Keys.ai's own models.** The five pages in `generated/sites` are
produced by `core/site_builder.py` running the local Ollama models:
`qwen2.5-coder:3b` writes the plan (brand, copy, sections, accent) for each
brief, and the page is then rendered from that plan through one of the ten
design studios — a different studio per page, pinned so the set cannot converge
on one layout. Each folder holds `plan.json`, `plan.raw.txt`,
`index.rendered.html` and `index.html`.

Rebuild them yourself:

```bash
python qa_artifacts/build_sites_with_local_model.py                 # default: fast
BUILD_SPEED=custom BUILD_WRITER=qwen3:8b python qa_artifacts/build_sites_with_local_model.py
```

`BUILD_SPEED=custom` also lets qwen3:8b write the whole page instead of
rendering the plan. On this machine that runs at roughly 20 minutes per page
(8B, CPU), which is why the recorded run used the plan path. The five pages
here were built and audited in about four minutes total.

**Verification** (`python qa_artifacts/verify_examples.py`):

| Check | Result |
| --- | --- |
| Pages built | 5 / 5 |
| Static checks + real Chromium audit | 5 / 5 pass, 0 console errors, no dead anchors, no 375 px overflow |
| Distinct documents | yes — five different SHA-256 hashes |
| Studios | Brutalist, Swiss, Cinematic, Organic, Aurora |
| Runnable examples (dashboards, Electron, PyQt, MySQL helper) | 7 / 7 pass |

Full details, including per-page check output, are in
`qa_artifacts/reports/example_build_verification.json`.

**Reference builds.** The dashboards, desktop, Electron, Android and MySQL
folders are hand-built exemplars of the structure `core/build_recipes.py` now
requires from the agent. They are the shape the local model is told to produce,
and each one runs today, which is what makes them useful as a target. They were
not generated by the model in this session — the table says so rather than
implying otherwise.

## MySQL

`database/mysql/` creates `keysai_shop` (4 tables, 1 view, 5 queries).
Copy `.env.example` to `.env`, set `DB_PASSWORD`, then:

```bash
cd database/mysql && pip install pymysql && python connect.py
```

The example dashboards each ship their own `schema.sql` and `.env.example` too.

## Why the model no longer produces a portfolio for a dashboard

`core/brief_spec.py` analyses the request before anything runs. A dashboard,
data tool, login or API integration is an **application**: it is routed to the
coding agent, not the page renderer, and if the brief does not state its data
source, metrics, chart types, stack or scope, `crown_code` returns
`NEED REQUIREMENTS` and builds nothing until the questions are answered.
`core/build_recipes.py` then hands the agent the concrete file layout, run
command and verification step for that kind of artifact.
