## A. Executive summary

Ten defects found by the audit were fixed in source, each with a regression
test. Two capabilities the audit identified as entirely absent were added: an
encrypted credential store and a local code-intelligence layer (indexed files,
Python symbols, imports, targeted search) exposed as the read-only
`repo_inspect` tool.

| # | What was wrong | What it is now |
|---|---|---|
| 1 | The coding agent's permission handler was `lambda ev: True` — it approved its own deletes, installs and shell commands | Risk policy in `core/agent_permissions.py`: reads and workspace writes run unattended, installs/network/out-of-workspace need the user, destructive and credential access are refused even with no UI to ask |
| 2 | `agent_control.scrub` raised `IndexError` on any bare key-shaped token | Rewritten masker; never raises, handles bare keys, headers, JWTs, bytes, unicode, 5 000-char input |
| 3 | Typed coding requests routed to `live_code`, a tool that does not exist → "Unknown tool" | Routed to `crown_code`; unknown tools now return `ok=False` instead of a success whose payload says "Unknown tool" |
| 4 | Two coroutines drained the dashboard command queue; replies were non-deterministic | One owner. The desktop app claims the queue; the dashboard's own consumer only starts when nothing claimed it |
| 5 | Mutating dashboard routes were unauthenticated | Token required for `/api/command`, `/api/settings*`, `/api/google/*` and WS control messages; constant-time compare; read-only routes unchanged |
| 6 | Three modules read-modify-wrote `config/api_keys.json` with no lock and non-atomic writes | One writer (`core/config_store.py`): process-wide lock, temp-file + `os.replace`, corrupt files quarantined, all four writers routed through it |
| 7 | Provider keys and Google OAuth tokens sat in plaintext | Encrypted with Windows DPAPI (no new dependency); the JSON now holds only non-secret settings. **Already applied to this machine's config: 4 credential entries moved, verified, nothing lost** |
| 8 | Gemini provider's deadline was dropped whenever `http_options` was supplied | Timeout merged into the supplied options |
| 9 | The dashboard answered on a hard-coded Gemini model regardless of provider | Uses `core.llm_client.complete("brain", …)` |
| 10 | No code intelligence anywhere | `core/repo_index.py` + `repo_inspect` tool |

Verification status: **311 regression tests pass** (was 236), **400 unittest
tests across 11 repository test files pass**, both script suites pass, every
touched module compiles and imports. The application was **not** launched
interactively (it needs a microphone and a live Gemini session) and the

## G. Known limitations

1. **The external coding agent is untouched.** `crown_code` still drives
   `C:/Users/harma/Desktop/PROJECTS/Crown CODE/dist-headless/headless.js`. Its
   planner, tool set, self-repair loop and policy engine are outside this
   repository and were not modified or re-verified. The app-side gate added here
   can refuse what that process asks about; it cannot make it ask.
2. **`config/certs/` is unchanged.** The TLS private key the audit found is
   still on disk in plaintext. Deleting or re-issuing it could break a working
   integration, so that decision is left to the owner. `.gitignore` now excludes
   it. Recommendation: confirm whether it is in use, then either move it into
   the encrypted store or remove it.
3. **Provider migration is partial.** Two call sites moved to the shared client;
   six tools still construct Gemini clients directly (credential-correct, not
   provider-agnostic). Each has a genuine Gemini-only capability or needs its
   prompt reshaped for another API — listed in §C.
4. **No canonical tool-spec object.** The tool set is still three coordinated
   places (declaration, handler registry, permission list). A consistency test
   now fails loudly when they drift, which is cheaper than a refactor of a
   35-entry literal, but the drift *prevention* is a test, not a type.
5. **No standardised tool-result type.** Unknown tools and crashes now return
   `ok=False`; most tools still return prose. Full result classification
   (timeout / permission / invalid input / verification failure) is not done.
6. **No multi-language test discovery or build orchestration.** The agent still
   does not inspect a project's manifest, choose `pytest`/`npm test`/`gradle`,
   or run a browser acceptance pass on generated projects. This is the largest
   gap for the "verified build system" goal.
7. **No GitHub integration, no MCP gateway.** Neither exists; neither was added.
8. **Memory and continuity are unchanged.** Live-path history is still RAM-only
   with a session-end summary; brain history is still a 12-item deque.
9. **Secrets are tied to the Windows user.** `config/secrets.enc` decrypts only
   for the account that wrote it. Copying the folder to another machine (or
   another Windows user) loses the credentials — by design, but it must be in
   the backup guidance.
10. **First-run migration is one-shot per process.** If `secrets.enc` is deleted,
    the JSON no longer holds the values; restore from a backup of
    `config/secrets.enc`.

## H. Rollback and reproducibility

**This directory is not a Git repository** (`git rev-parse` → *fatal: not a git
repository*), so no commit-level rollback point exists. That is a limitation of
the starting state, not of this pass.

What is available:

- **Configuration:** before the credential migration, `config/api_keys.json` was
  copied to a temporary path, the migration was verified against it (nothing
  lost, nothing left in plaintext), and only then was the copy removed. Reversal
  is possible with `config_store.load()` → write the dict back to the JSON, since
  the decrypted values are intact in `config/secrets.enc`.
- **Source:** the audit in `audit_output/` records the pre-change state of every
  file discussed here (`02_FILE_INVENTORY.csv` with sizes, `12_TESTING…` with the
  236-test baseline), which is enough to reconstruct behaviour, not bytes.

Recommended, in this order:

1. `git init && git add -A && git commit` **now** — `.gitignore` is already in
   place, so credentials stay out.
2. Back up `config/secrets.enc` (encrypted, safe to copy) together with
   `config/api_keys.json` (settings only).
3. Keep `python -m unittest qa_artifacts.regression_tests.test_*` and the 11
   repository test files as the gate for the next change.
